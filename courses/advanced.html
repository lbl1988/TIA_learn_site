🛰 PROFIdrive 标准报文与 V90 PN 组态

PROFIdrive 是基于 PROFINET 的驱动标准协议，PLC 与伺服之间通过 标准报文 交换控制字、状态字、位置、速度、力矩等数据。V90 PN 支持多种报文，根据应用场景选择：

报文名称适用场景关键信号
报文 1基础速度控制简单变频、速度给定STW1 控制字 + 主设定值
报文 2扩展速度控制速度 + 附加数据STW1 + STW2 + 附加设定值
报文 3标准定位控制伺服定位（S7-1200 常用）控制字 + 目标位置 + 状态字 + 实际位置
报文 105扩展定位控制S7-1500T 高级运动扩展控制字 + 目标位置 + 力矩限制
报文 116电子齿轮/凸轮同步控制、飞剪主值 + 从值 + 相位偏移
V90 PN 组态步骤

V90 PN 的组态在 TIA Portal 设备组态 中完成，而非独立软件：

// V90 PN 组态流程
1. 项目树 → 设备组态 → 添加 PROFINET I/O
2. 硬件目录 → 驱动器 → V90 PN → 拖拽到 PROFINET 网络
3. 设置 V90 PN 的 PROFINET 设备名（如 V90_Line1）
4. 右键 V90 → 属性 → 选择报文类型（如报文 3）
5. 添加工艺对象 TO_Positioning 到 PLC 项目
6. 在 TO 属性中绑定 V90 PN 接口（自动匹配报文）
7. 设置轴参数：脉冲当量、编码器分辨率、方向
报文 3 数据结构详解

报文 3 是 S7-1200 + V90 PN 定位控制的 最常用报文，数据结构如下：

// 报文 3 数据交换区（PLC → V90）
// STW1 控制字（16 bit）
Bit0: 切换到运行模式    Bit1: 使能运行
Bit2: 使能输出         Bit3: 无故障
Bit4: 停止             Bit5: 暂停
Bit6: 绝对定位启动     Bit7: 相对定位启动
...
// 主设定值（32 bit）：目标位置（INT 单位）
"Axis".TargetPosition

// 报文 3 数据交换区（V90 → PLC）
// ZSW1 状态字（16 bit）
Bit0: 就绪             Bit1: 运行中
Bit2: 输出已使能       Bit3: 故障
Bit4: 达到目标         Bit5: 暂停
...
// 主实际值（32 bit）：当前位置
"Axis".ActualPosition

💡 脉冲当量：1 脉冲对应的实际位移。公式：脉冲当量 = 丝杠导程 / (编码器线数 × 电子齿轮比)。设定错误会导致定位偏差！

⚙ 轴工艺对象 TO_Positioning 详解

S7-1200/1500 的运动控制基于 轴工艺对象（Technology Object, TO）。TO 封装了所有伺服控制逻辑，用户通过调用 工艺指令（如 MC_Power、MC_Home、MC_MoveAbsolute）实现运动控制。

工艺对象功能适用 CPU说明
TO_Positioning定位轴S7-1200/1500绝对/相对定位、回原点
TO_SpeedAxis速度轴S7-1200/1500仅速度控制，不定位
TO_ExternalEncoder外部编码器S7-1200/1500读取外部编码器位置
TO_Cam电子凸轮S7-1500T主从轴位置耦合
TO_Gear电子齿轮S7-1500T主从轴速度耦合
TO_OutputCam输出凸轮S7-1200/1500位置触发数字量输出
TO_Positioning 关键参数
// TO_Positioning 组态参数
// ① 驱动接口：绑定 V90 PN 的报文 3 接口
// ② 编码器：增量式 / 绝对值（V90 支持绝对值编码器）
// ③ 脉冲当量：1 脉冲 = 实际位移量（mm/°）
//    例：丝杠导程 5mm，编码器 2500 线 → 脉冲当量 = 5/2500 = 0.002mm
// ④ 轴方向：正向/反向（根据机械安装确定）
// ⑤ 软限位：软件行程限制（正向最大 + 反向最大）
Axis.HomePosition = 0.0     // 回原点位置
Axis.PositionModulus = 360.0  // 模数（°为 360，mm 为行程）
Axis.PeriodLength = 0.0     // 周期长度（0 = 非模态轴）

// ⑥ 动态参数
Axis.MaxVelocity = 3000.0  // 最大速度（mm/s 或 °/s）
Axis.MaxAcceleration = 10000.0  // 最大加速度
Axis.MaxDeceleration = 10000.0  // 最大减速度
Axis.Jerk = 50000.0        // 加加速度（平滑度）
工艺指令调用示例
// 完整定位控制流程
// Step 1: 使能轴
MC_Power(
  Axis := "Axis",
  Enable := "Start",
  RegulatorOn := TRUE,      // 位置环使能
  DriveStart := TRUE        // 驱动器启动
);

// Step 2: 回原点（上电首次或丢失绝对值后）
MC_Home(
  Axis := "Axis",
  Start := "HomeStart",
  HomingMode := DIRECT,     // 绝对值编码器直接回零
  Position := 0.0           // 回原点目标位置
);

// Step 3: 绝对定位
MC_MoveAbsolute(
  Axis := "Axis",
  Execute := "MoveStart",
  Position := 150.0,        // 目标位置 150mm
  Speed := 1000.0,          // 移动速度
  Direction := POS,         // 正向移动
  BufferMode := ABORTING    // 打断当前运动
);

// Step 4: 等待到位
MC_Halt(Axis := "Axis", Execute := "StopAxis");

💡 BufferMode 参数控制运动衔接：ABORTING 打断当前运动立即执行新指令；BUFFERED 当前运动完成后执行新指令；Blending 两段运动平滑过渡。

🏠 回原点（Homing）3 种模式实战

伺服上电后必须 先回原点 才能进行定位。回原点的目的是 建立坐标系零点。S7-1200 + V90 PN 支持 3 种常用回原点模式：

模式原理适用编码器硬件需求
DIRECT直接使用绝对值编码器位置绝对值编码器无额外传感器
LIMIT_SWITCH碰限位开关 + 逼近零点增量编码器原点开关 + 接近开关
ENCODER_INDEX寻找编码器 Z 脉冲索引增量编码器无额外传感器
ADJUST手动调整到零位任意人工辅助
DIRECT 模式（绝对值编码器）

最简单的方式，V90 绝对值编码器 上电即知位置，无需物理回原点动作：

// DIRECT 回原点
MC_Home(
  Axis := "Axis",
  Start := "HomeBtn",
  HomingMode := DIRECT,
  Position := 0.0,          // 当前位置作为零点
  BufferMode := ABORTING
);

// 时序：
// ① 轴使能 → MC_Power
// ② 触发 HomeBtn → MC_Home(DIRECT)
// ③ 零点 = 当前编码器位置 → 标记为 0.0
// ④ 回原点完成 → MC_Home.Done = TRUE

💡 绝对值编码器电池掉电后会丢失位置，需要重新回原点。建议 每次开机自动回原点，即使使用绝对值编码器。

LIMIT_SWITCH 模式（增量编码器）

增量编码器 上电不知道位置，需要通过原点开关找到零点：

// LIMIT_SWITCH 回原点流程
1. 轴以搜索速度朝设定方向移动
2. 碰到原点开关（限位开关）后减速
3. 离开原点开关后继续缓慢移动
4. 找到编码器下一个 Z 脉冲 → 确立零点

MC_Home(
  Axis := "Axis",
  Start := "HomeBtn",
  HomingMode := LIMIT_SWITCH,
  HomingSwitch := I0.0,      // 原点开关输入
  Position := 0.0,
  HomeVelocity := 100.0,     // 搜索速度（慢）
  StartVelocity := 1000.0,   // 初始速度（快）
  Direction := NEG           // 回原点方向
);

注意事项：原点开关必须在 行程范围内，且离机械零点有一定距离（防止超程）。编码器 Z 脉冲精度决定零点重复精度。

🚀 S7-1500T 电子凸轮 / 同步 / 飞剪

S7-1500T（Technology CPU）在 S7-1500 基础上增加了 T 特性，支持高精度运动控制。通过 PROFINET IRT 实现 1ms 同步周期，适合飞剪、电子凸轮、多轴同步等高速应用。

功能工艺对象指令典型应用
电子凸轮TO_CamMC_CamIn / MC_CamOut包装机封口、灌装机
电子齿轮TO_GearMC_GearIn / MC_GearOut多轴同步、龙门架
飞剪组合 Cam + AxisMC_CamTrack定尺剪切、线材切割

电子凸轮原理

电子凸轮用 主轴的位置 驱动 从轴的位置，关系由凸轮曲线定义。主轴可以是实轴（如编码器）或虚拟轴：

// 电子凸轮示例：封口辊跟随包装膜
// 主轴：编码器检测包装膜进给位置
// 从轴：封口伺服按凸轮曲线跟随主轴

// 1. 创建凸轮曲线（TIA 中图形化编辑）
//    主轴 0~360° 对应从轴 0~100mm（正弦或自定义曲线）

// 2. 建立凸轮耦合
MC_CamIn(
  Master := "MasterAxis",     // 主轴（编码器轴）
  Slave := "SlaveAxis",       // 从轴（封口伺服）
  Start := "EngageBtn",
  CamTable := "CamDB".CamData,  // 凸轮曲线数据
  MasterValueSource := ACTUAL  // 用主轴实际值
);

// 3. 解除凸轮耦合
MC_CamOut(Slave := "SlaveAxis", Start := "DisengageBtn");
飞剪控制

飞剪是典型的 移动中剪切 工艺：材料连续进给，剪刃按定尺周期同步运动，实现不停机剪切：

// 飞剪控制逻辑
// 1. 测量材料速度（主轴编码器）
// 2. 计算剪刃目标速度 = 材料速度 × 剪刃直径 / 材料直径
// 3. 剪刃跟随材料做同步运动（CamIn）
// 4. 到位时触发剪切（OutputCam）
// 5. 剪切完成后剪刃快速回原点

// 飞剪关键代码片段
MC_CamIn(
  Master := "MaterialEncoder",   // 材料编码器
  Slave := "ShearAxis",          // 剪刃轴
  Start := "StartCut",
  CamTable := "ShearCam".Data,
  SynchronizationError := 1.0    // 同步误差允许值
);

// 剪切触发（剪刃到达剪切点时）
MC_OutputCam(
  Axis := "ShearAxis",
  Start := "CamActive",
  Output := Q0.5,                // 剪切气缸
  CamTable := "ShearCam".Data
);

💡 S7-1500T 必须使用 IRT 等时同步模式（Isochronous Real-Time），PLC 扫描周期 = PROFINET 周期 = 1ms，确保多轴同步精度。

安全程序与标准程序分离

F-CPU 的程序分为 两个独立区域：

// F-CPU 程序结构
📁 PLC 程序
├── 📂 F 程序（安全区）
│   ├── F-OB1 安全主循环
│   ├── F-FB_ESTOP 急停功能块
│   ├── F-FB_SafetyDoor 安全门功能块
│   └── F-FB_LightCurtain 光栅功能块
├── 📂 标准程序（非安全区）
│   ├── OB1 主循环
│   ├── OB35 循环中断
│   └── 标准 FB/FC
└── 📂 F 符号表
    ├── F-I/O 标签（F_I0.0, F_Q0.0）
    └── F-内部变量

💡 安全程序和标准程序 严格隔离。F 程序只能使用 F_ 前缀的指令和 F-I/O 变量，标准程序无法直接访问 F 变量，只能通过 安全接口 交换状态信息。

SIL 安全等级

SIL（Safety Integrity Level）是 IEC 61508 标准定义的 安全完整性等级，分为 SIL1~SIL4，工业常用 SIL2 和 SIL3：

等级PFD 范围适用场景硬件要求
SIL110⁻¹ ~ 10⁻²一般安全要求单通道
SIL210⁻² ~ 10⁻³冲压机、注塑机双通道
SIL310⁻³ ~ 10⁻⁴汽车产线、化工双通道 + 诊断
SIL410⁻⁴ ~ 10⁻⁵铁路信号三通道

S7-1200F 最高支持 SIL2，S7-1500F 支持 SIL3。

🔌 F-I/O 模块与安全传感器接线

安全回路的核心是 双通道冗余。安全传感器（急停、安全门、光栅）必须以 双通道方式 连接到 F-I/O 模块。

安全光栅双通道 OSSDAF-DI 双通道 + TEST遮挡时输出低电平
安全继电器双通道输出F-DI 监控 + F-DO 控制监控触点反馈

// 双通道急停接线
// 急停按钮：两副常闭触点
// 触点 1 → F-DI0.0（安全输入 0）
// 触点 2 → F-DI0.1（安全输入 1）
// 正常：两触点均闭合 → F-DI0.0 = 1, F-DI0.1 = 1
// 急停：两触点均断开 → F-DI0.0 = 0, F-DI0.1 = 0

// TIA 中配置 F-DI 通道
// 通道 0: 急停按钮 → 设置为"双通道"
// 通道 1: 急停反馈 → 设置为"检测反向"
// 两个通道必须同时一致，否则触发安全停机

🔒 F_ 安全指令集详解

F-CPU 提供专用的 F_ 前缀安全指令，这些指令在双通道中独立执行并比较结果。如果两个通道结果不一致，CPU 会进入 安全状态。

指令功能参数说明
F_ESTOP安全急停Input, Output, Reset触发后输出断开并锁存
F_MUTE安全静音Input, Output, Ack确认报警后复位
F_DIS安全断开Input, Output条件满足时断开输出
F_TON安全通电延时IN, PT, Q与 TON 类似但双通道执行
F_TOF安全断电延时IN, PT, Q与 TOF 类似但双通道执行
F_SR / F_RS安全触发器S, R, QRS/SR 触发器安全版
F_AND / F_OR安全逻辑运算IN1, IN2, OUT双通道 AND/OR
F_EQU安全比较IN1, IN2, OUT安全等值比较
F_ESTOP 急停实现
// F_ESTOP 实现双通道急停
// 两个 F-DI 通道必须同时断开

|-- F_ESTOP --|
    Input1 := F_I0.0,    // 急停通道 1
    Input2 := F_I0.1,    // 急停通道 2
    Output1 => F_Q0.0,   // 安全输出 1（控制电机）
    Output2 => F_Q0.1,   // 安全输出 2（双通道）
    Reset := M0.0        // 复位按钮

// 逻辑：
// Input1=1 AND Input2=1 → Output=1（正常运行）
// Input1=0 OR Input2=0 → Output=0（急停触发）
// 必须两个输入都恢复 + Reset 才能解除急停
安全门 + 光栅组合逻辑
// 安全监控组合
// 急停（F_I0.0/0.1）+ 安全门（F_I0.2/0.3）+ 光栅（F_I0.4/0.5）

// 急停 + 安全门：OR 逻辑
|-- F_OR --|
    IN1 := F_ESTOP.Output,   // 急停状态
    IN2 := F_SafetyDoor.Output,  // 安全门状态
    OUT => M_Fault

// 最终安全输出：
|-- F_AND --|
    IN1 := "Interlock".OK,   // 联锁条件
    IN2 := F_Guard.Output,   // 光栅状态
    OUT => F_DriveSafe       // 驱动器安全使能

// SIL3 验证：
// 1. 所有 F_ 指令双通道执行
// 2. 每次扫描比较两个通道结果
// 3. 不一致 → 立即进入安全状态
// 4. F-DO 输出断开（Safe Torque Off）

💡 安全程序中 禁止使用跳转指令（JMP/LBL），避免程序流不可预测。每个 F-程序块必须是 单入口、单出口。

// WinCC VBS: 班次报表生成
Sub GenerateShiftReport()
  Dim objReport, objConn, strSQL
  Dim dNow, dShiftStart
  
  Set objReport = CreateObject("WinCC.ReportGenerator")
  Set objConn = CreateObject("ADODB.Connection")
  
  // 计算当前班次开始时间
  dNow = Now()
  If Hour(dNow) >= 8 And Hour(dNow) < 16 Then
    dShiftStart = Date() & " 08:00:00"
  ElseIf Hour(dNow) >= 16 Then
    dShiftStart = Date() & " 16:00:00"
  Else
    dShiftStart = Date() & " 00:00:00"
  End If
  
  // 查询变量记录生成报表
  objConn.Open "Provider=SQLOLEDB;Server=.\WINCC;Database=WinCC"
  strSQL = "SELECT Value, TagName FROM Archives " & _
           "WHERE DateTime BETWEEN '" & dShiftStart & "' AND '" & dNow & "'"
  // ...处理数据...
  
  // 生成报表
  objReport.PrintReport "ShiftReport.rpt", "", 1
  objConn.Close
End Sub

📝 TRACE 功能配置详解

TRACE 是 TIA Portal 内置的 数据采集与分析工具，类似逻辑分析仪，可记录 PLC 变量的变化轨迹，用于故障诊断和程序调试。

CPU 类型TRACE 数量最大信号数存储深度
S7-12002 条每条 16 信号10,000 采样点
S7-1500多条（10+）每条 32 信号100,000 采样点
S7-1500T多条每条 32 信号实时同步采集
TRACE 配置步骤
// TRACE 配置步骤
1. 项目树 → CPU → 轨迹 → 添加新 Trace
2. 添加信号（最多 16 个：位/整数/实数/时间）
3. 选择采样 OB：OB1 循环 或 OB35 中断
4. 设置采样频率（每 N 个 OB 周期采样一次）
5. 选择触发模式
6. 下载 TRACE 配置
7. 激活 TRACE → 等待触发 → 上传记录

// 信号添加示例
// - "Motor".StartRun    (BOOL, 位信号)
// - "Motor".Current     (REAL, 模拟量)
// - "Axis".Position     (REAL, 位置值)
// - "Alarm".Code        (WORD, 状态字)
采样策略与 OB 同步

采样周期必须与 OB 同步，确保数据的时序正确性：

// 采样周期设置
// 选项 1: 跟随 OB1 循环（每个扫描周期采样）
//   → 适合普通逻辑调试
//   → 采样频率 = PLC 扫描周期（1~10ms）
//   → 设置 N=1，每个 OB1 周期采样一次

// 选项 2: 跟随 OB35 循环中断
//   → 适合高速信号采集
//   → OB35 默认周期 = 1ms（可改）
//   → 设置 N=1，每 1ms 采样一次

// 选项 3: 倍频采样
//   → 每 N 个 OB 周期采样一次
//   → 例：N=10 → 每 10ms 采样一次
//   → 用于长时间趋势记录

💡 采样频率越高，存储的数据量越大。S7-1200 存储深度为 10,000 点，采样周期 1ms 时可记录 10 秒数据，采样周期 100ms 时可记录 1000 秒。

⚡ 三种触发模式详解

TRACE 提供 三种触发模式，适应不同的诊断需求：

触发模式工作方式适用场景
立即记录激活后立即开始记录已知故障时间点的调试
变量触发变量满足条件时开始记录捕获特定事件发生前后
无触发器监视循环记录最新数据（环形缓冲）持续监视、故障黑匣子
变量触发 + 预触发

变量触发模式支持 预触发（Pre-Trigger），即触发前的数据也会被记录，这对诊断瞬时故障至关重要：

// 变量触发配置
// 触发条件："Alarm".Code == 16#8090（故障代码）
// 预触发：50% 存储深度（触发前 5000 点）
// 后触发：50% 存储深度（触发后 5000 点）

// 工作流程
1. TRACE 激活 → 环形缓冲开始填充
2. 缓冲区满 → 新数据覆盖最旧数据
3. 触发条件满足 → 锁定缓冲区
4. 继续记录后触发数据
5. 存储满 → 停止记录
6. 上传记录 → 分析触发前后的数据
无触发器监视（黑匣子模式）

无触发器模式就是 飞机黑匣子 原理——始终循环记录最新数据，故障发生后保存当前缓冲区内容：

// 黑匣子配置
1. TRACE 配置为"无触发器监视"
2. 环形缓冲区始终保持最新数据
3. 故障发生后（如 CPU STOP），缓冲区自动保存
4. 下载后分析故障前的运行轨迹

// 实现方式
// TRACE 激活 → 始终循环记录
// CPU STOP 时自动保存到内部存储
// 下次启动后通过 TIA 上传
// 保存格式：.csv / .bin

// 高级：程序控制保存
// 在故障 OB 中调用 TRACE_SAVE 指令
// 将当前 TRACE 记录保存到存储卡
// 文件命名带时间戳：TRACE_20240115_120000.csv

💡 黑匣子模式是产线级应用的 标配功能。建议每个 CPU 至少配置 1 条黑匣子 TRACE，始终记录关键变量，故障时自动保存。

🔬 逻辑分析器与组合测量

TRACE 记录上传后，TIA 内置的 逻辑分析器 以图形化方式展示波形，支持多信号对比和高级分析：

逻辑分析器功能
// 逻辑分析器操作
1. 导入 TRACE 记录（.bin / .csv 文件）
2. 所有信号以波形形式显示
3. 支持缩放、滚动、时间测量
4. 光标移动查看精确数值
5. 多信号对齐对比（检查时序关系）
6. 组合测量：不同记录的信号叠加

// 典型诊断场景
// ① 电机启动时电流冲击分析
// ② 伺服定位过程中的位置/速度/力矩曲线
// ③ PROFIBUS/PROFINET 通信时序分析
// ④ 报警发生前后的程序执行轨迹
// ⑤ PID 调节过程的响应曲线分析
实战：定位抖动故障排查

案例：V90 伺服定位到位后有 ±0.5mm 抖动，使用 TRACE 排查：

// 步骤 1: 设置 TRACE
// 信号：设定位置、实际位置、速度、力矩、使能状态
// 触发：到位信号 MC_MoveAbsolute.Done
// 预触发：30%，后触发：70%
// 采样周期：1ms（OB35）

// 步骤 2: 分析波形
// 观察：到位后力矩在 ±50% 之间振荡
// 结论：PID 参数调整不当，需降低比例增益
// 验证：调整后重新 TRACE 确认抖动消除

// 步骤 3: 保存记录到存储卡
// TRACE 记录可保存为 CSV，用 Excel 二次分析
// 支持导出波形截图用于报告

💡 TRACE 是高级工程师的 核心诊断工具。遇到疑难杂症时，一条精心配置的 TRACE 记录胜过十次代码审查。建议在现场调试时养成 先 TRACE 再动手改 的习惯。
