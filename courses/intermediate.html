🏗 结构化编程块体系架构

TIA Portal 的 块模型 是结构化编程的核心，将程序拆分为不同职责的"积木"，通过调用组装成完整应用：

1OB1 主循环
调度中心，不写逻辑
→
2调用 FB/FC
按功能拆分子程序
→
3FB 读写 DB
操作实例 DB 持久数据
→
4FC 读写 M/DB
纯计算无状态
→
↺ 返回 OB1

核心原则：

  • OB1 只做调度：不在 OB1 写任何线圈/逻辑，仅按顺序调用各个 FB/FC。
  • FC 无状态：每次调用的临时变量独立，不记忆上一次结果，适合纯计算。
  • FB 有状态：通过绑定的 实例 DB（背景 DB） 保存静态数据，多次调用之间保持状态。
  • DB 分层：全局 DB 存共享数据（配方、标签），实例 DB 存单个 FB 的运行状态。
  • 高内聚低耦合：每个 FB 封装一个设备/功能，接口（Input/Output/InOut）明确。
⚡ OB 组织块：程序执行的入口

OB（Organization Block）是 PLC 程序的 执行入口，由操作系统调度，不能互相调用。S7-1200/1500 常用 OB 类型：

OB 编号名称触发条件典型用途
OB1程序循环每扫描周期执行一次主调度：按序调用各 FB/FC
OB100启动 OBCPU 上电/重启时执行一次初始化：复位变量、设置默认值
OB101暖启动STOP→RUN 切换暖启动初始化
OB35循环中断固定间隔（默认 100ms）周期性任务：PID 运算、数据采集
OB30~OB38循环中断可配置 1~100ms高精度循环任务
OB40~OB47硬件中断数字量/模拟量信号跳变快速响应：急停、高速计数
OB82诊断中断模块故障/变化读取诊断信息、触发报警
OB86机架故障PROFINET IO 设备掉线网络异常处理、切换到安全模式
OB121编程错误访问不存在的地址防止 CPU 停机、错误恢复
OB122I/O 访问错误访问故障模块记录错误、切换输出状态
OB1 调度模板
// OB1 主循环 — 只做调度，不写逻辑
// 推荐调度顺序
CALL FB_ErrorHandler     // 1. 错误处理优先级最高
CALL FB_SafetyLogic       // 2. 安全回路
CALL FB_Conveyor         // 3. 输送机控制
CALL FB_Mixer             // 4. 搅拌罐控制
CALL FC_DataExchange     // 5. 数据交换
CALL FC_HMI_Update        // 6. HMI 刷新

// ❌ 禁止在 OB1 写直接输出
// Q0.1 := TRUE;  // 错误！应封装到 FB 内部

💡 OB1 扫描周期内所有 FB/FC 按顺序执行，前一个 FB 的输出会被后一个 FB 读到。合理安排调用顺序至关重要。

OB100 启动初始化
// OB100 启动组织块 — 只执行一次
// 典型初始化操作

// 1. 复位所有中间标志
FOR i := 0 TO 31 DO
    "SystemDB".ErrorFlags[#i] := FALSE;
END_FOR;

// 2. 加载默认配方
CALL FB_RecipeLoader(
    RecipeID  := 1,
    RecipeDB  => "RecipeDB",
    Done       => StartupDone
);

// 3. 清零累计量

"ProductionDB".StartTime   := RD_LOC_T(DT);

🔀 FC vs FB：何时用哪个？

FC（Function）和 FB（Function Block）的核心区别在于 是否需要记忆状态：

特性FCFB
静态数据无（每次调用临时变量）有（背景 DB 持久存储）
状态记忆不记忆上次调用记忆并可读取历史状态
定时器用 IEC 定时器需额外 DB定时器实例存储在背景 DB
多次实例可随意复用每个实例需独立 DB
典型用途数学计算、字符串处理、纯逻辑设备封装、PID、状态机、计数器
执行速度稍快（无 DB 访问）稍慢（读写背景 DB）
FC 示例：纯计算
// FC_CalcFlow.scl — 纯流量计算，无状态
FUNCTION FC_CalcFlow : REAL
// 输入：
//   InletPress : REAL  // 进口压力
//   OutletPress: REAL  // 出口压力
//   PipeDia    : REAL  // 管径 mm
// 输出：
//   函数返回值 = 流量 m³/h

VAR_TEMP
    DeltaP : REAL;
    Area   : REAL;
END_VAR_TEMP

DeltaP := #InletPress - #OutletPress;
Area   := 3.14159 * (#PipeDia / 1000.0) * (#PipeDia / 2000.0);
FC_CalcFlow := 3600.0 * SQRT(2.0 * #DeltaP / 1000.0) * #Area;

✅ FC 内的 DeltaP、Area 是临时变量，调用后释放。下次调用重新计算。

FB 示例：设备封装
// FB_Starter.scl — 电机启动器，有状态
FUNCTION_BLOCK FB_Starter
VAR_INPUT
    StartBtn   : BOOL;
    StopBtn    : BOOL;
    Overload   : BOOL;
    RatedCurrent: REAL := 10.0;
END_VAR_INPUT

VAR_OUTPUT
    MotorRun   : BOOL;
    AlarmCode  : INT;
END_VAR_OUTPUT

VAR
    StartReq   : BOOL;      // 自锁状态（保持）
    RunHours   : REAL;     // 累计运行小时数（保持）
    LastStart  : DATE_AND_TIME;  // 上次启动时间（保持）
END_VAR

// 启保停逻辑
StartReq := (#StartBtn OR #StartReq)
                AND NOT #StopBtn
                AND NOT #Overload;
MotorRun := #StartReq;

// 累计运行时间
IF #MotorRun THEN
    RunHours := #RunHours + 0.00278;  // 10ms = 0.00278h
END_IF;

// 报警代码
IF #Overload THEN
    AlarmCode := 101;  // 过载
ELSIF #StopBtn THEN
    AlarmCode := 0;    // 正常停机
END_IF;

✅ FB 内的 StartReq、RunHours、LastStart 存储在 实例 DB 中，调用之间保持不变。

💾 DB 数据块：优化块访问与多实例

S7-1200/1500 默认使用 优化块访问（Optimized Block Access），所有变量通过 符号名 访问，不再使用绝对偏移地址。

DB 类型创建方式绑定关系典型用途
实例 DB（背景 DB）FB 属性 → 生成实例 DB绑定 FB 的接口和内部变量每个 FB 实例独立存储
全局 DB新建 DB → 手动添加变量无绑定，通用数据容器配方、生产数据、HMI 共享
UDT 类型 DB先建 UDT 类型，再用其建 DB基于用户自定义结构多设备共用同一数据结构

多实例 FB 调用
// 同一 FB 类型，不同实例 DB → 多实例
// 调用 FB_Starter 三次，各用独立 DB

CALL FB_Starter
(
    StartBtn    := "Tags".M1_Start,
    StopBtn     := "Tags".M1_Stop,
    Overload    := "Tags".M1_OL,
    MotorRun    => "Tags".M1_Run,
    AlarmCode   => "Tags".M1_Alarm
);

// 自动使用 FB_Starter 的实例 DB（系统分配）
// 或指定：
CALL FB_Starter, DB_Starter_M1 (...);

💡 S7-1200 默认自动分配实例 DB 编号（1, 2, 3...），可在 FB 属性 → 实例 DB 中手动指定编号和名称。

📝 SCL 基础语法与 LAD 对比

SCL（Structured Control Language）是 结构化控制语言，语法类似 Pascal，是 TIA Portal 中功能最强大的编程语言。从 LAD 转向 SCL 需要理解以下核心差异：

特性LAD 梯形图SCL 结构化文本
表达方式图形化（触点/线圈）文本（类 Pascal）
逻辑表达AND/OR 串联并联AND / OR / XOR / NOT
控制流无（只能顺序执行）IF / CASE / FOR / WHILE / REPEAT
运算基础加减乘除完整数学库 + 字符串 + 数组
复杂度适合简单逻辑适合复杂算法/数据处理
可读性电工直觉程序员直觉
一行启保停
// LAD: 启保停电路需要 3 个元素
// |--Start--┬─┤/├──Motor--|
//          │  Stop        
//          └─Motor(自锁) 

// SCL: 一行搞定
Motor := (#StartBtn OR Motor) AND NOT #StopBtn;

// 读作：电机 = (启动按钮 OR 电机自身) AND NOT 停止按钮

SCL 中 `#` 前缀表示 块接口参数（Input/Output/InOut），无前缀表示 全局 DB 变量。

SCL 关键字速查
// SCL 关键字分类

// 1. 控制流
IF ... THEN ... ELSIF ... ELSE ... END_IF;
CASE ... OF ... ELSE ... END_CASE;
FOR i := start TO end DO ... END_FOR;
WHILE condition DO ... END_WHILE;
REPEAT ... UNTIL condition END_REPEAT;

// 2. 块声明
FUNCTION FC_Name : ReturnType ... END_FUNCTION;
FUNCTION_BLOCK FB_Name ... END_FUNCTION_BLOCK;
DATA_BLOCK DB_Name ... END_DATA_BLOCK;

// 3. 变量声明
VAR_INPUT ... END_VAR_INPUT;
VAR_OUTPUT ... END_VAR_OUTPUT;
VAR_IN_OUT ... END_VAR_IN_OUT;
VAR_TEMP ... END_VAR_TEMP;
VAR ... END_VAR;   // FB 静态变量
🔀 IF / CASE / FOR 控制流实战

SCL 的控制流语句是其相对于 LAD 的最大优势，支持完整的结构化编程三要素：顺序、选择、循环。

IF 条件判断
// 单级 IF
IF #LevelHi THEN
    "Tags".Pump := FALSE;
END_IF;

// 多级 IF / ELSIF / ELSE
IF #Temp > 80.0 THEN
    Status := 3;       // 高温报警
    Cooling := TRUE;
ELSIF #Temp > 60.0 THEN
    Status := 2;       // 高温预警
    Cooling := FALSE;
ELSIF #Temp > 30.0 THEN
    Status := 1;       // 正常
ELSE
    Status := 0;       // 低温
END_IF;
CASE 多分支选择
// CASE 替代多路 IF，清晰表达多档位
CASE #SpeedLevel OF
    1 : Output := 33.0;    // 低速
    2 : Output := 66.0;    // 中速
    3 : Output := 100.0;   // 高速
    ELSE Output := 0.0;    // 默认停机
END_CASE;

// CASE 多值合并
CASE #DayOfWeek OF
    1, 2, 3, 4, 5 : IsWorkday := TRUE;
    6, 7 : IsWorkday := FALSE;
END_CASE;
FOR 循环
// FOR 循环：固定次数迭代
// 计算 8 路传感器平均值
Sum := 0.0;
FOR i := 0 TO 7 DO
    Sum := Sum + "SensorDB".Data[#i];
END_FOR;
Average := Sum / 8.0;

// FOR 循环：批量复位
FOR i := 0 TO 15 DO
    "OutputDB".Dout[#i] := FALSE;
END_FOR;
WHILE / REPEAT
// WHILE：先判断再执行（可能一次都不执行）
WHILE #BufferCount > 0 DO
    // 处理缓冲区数据
    CALL FC_ProcessOne(Index := #BufferIdx);
    BufferCount := #BufferCount - 1;
END_WHILE;

// REPEAT：先执行再判断（至少执行一次）
REPEAT
    Val := Val / 2.0;
    Iter := Iter + 1;
UNTIL ABS(Val) < 0.001 OR #Iter > 100
END_REPEAT;

💡 WHILE/REPEAT 可能导致扫描周期超时！PLC 循环内尽量用 FOR 或限制循环次数（如 REPEAT 最多 100 次）。

⏱ 沿信号检测与 IEC 定时器避坑

在 SCL 中实现 上升沿/下降沿检测 和 IEC 定时器调用 是两个经典难点，处理不当会出现"信号丢失"或"定时器乱跳"。

沿信号自写（R_TRIG/F_TRIG）
// 方法1：使用 R_TRIG 功能块
VAR
    RisingDetect : R_TRIG;   // 上升沿检测 FB
    FallingDetect: F_TRIG;   // 下降沿检测 FB
END_VAR

// 每个扫描周期调用
RisingDetect(CLK := #StartBtn);
FallingDetect(CLK := #StopBtn);

IF RisingDetect.Q THEN
    // 上升沿触发：启动按钮按下瞬间
    PulseStart := TRUE;
END_IF;

// 方法2：自写沿检测（无需 FB）
IF #Sensor AND NOT #Sensor_Old THEN
    // 上升沿
    RisingPulse := TRUE;
END_IF;
Sensor_Old := #Sensor;  // 保存当前值供下次比较

💡 R_TRIG 必须在 每个扫描周期 都调用，不能放在 IF 条件内。否则 CLK 变化期间不扫描会丢失沿信号。

IEC 定时器正确用法
// ❌ 错误：定时器放在 IF 条件内
IF #Start THEN
    TON1(IN := TRUE, PT := T#5S);  // 条件不满足时定时器停止！
END_IF;

// ✅ 正确：定时器放在主路径，EN 恒定
// 定时器声明
VAR
    TON1 : TON;
END_VAR

// 定时器调用（始终执行）
TON1(
    IN        := #Start,        // IN 条件
    PT        := T#5S,          // 预设时间
    Q         => TimerDone,
    ET        => Elapsed
);

// 使用定时器输出
IF #TimerDone THEN
    "Tags".Buzzer := TRUE;
END_IF;

💡 IEC 定时器的 IN 端信号在扫描周期内可能变化，但定时器的"内部计时"只在 调用时 更新。因此必须确保定时器指令每次扫描都被执行。

📇 数组、字符串与间接寻址

SCL 支持 一维/多维数组 和 间接寻址，是批量数据处理的利器。

数组声明与操作
// 在 DB 中声明数组
DATA_BLOCK DB_Sensors
BEGIN
    Temperatures : ARRAY[0..15] OF REAL;
    Pressures   : ARRAY[0..7]  OF REAL;
    StatusBits   : ARRAY[0..31] OF BOOL;
END;

// 数组元素访问
"DB_Sensors".Temperatures[0] := 25.5;
CurrentTemp := "DB_Sensors".Temperatures[#Index];

// 数组批量处理
FOR i := 0 TO 15 DO
    // 限幅：限制在 0~100℃
    IF "DB_Sensors".Temperatures[#i] > 100.0 THEN
        "DB_Sensors".Temperatures[#i] := 100.0;
    ELSIF "DB_Sensors".Temperatures[#i] < 0.0 THEN
        "DB_Sensors".Temperatures[#i] := 0.0;
    END_IF;
END_FOR;
字符串处理
// STRING 声明（最大 254 字符）
Message : STRING[128];
RecipeName : STRING[32];

// 字符串赋值
Message := 'System Ready';

// 字符串拼接（CONCAT_3 或 S_CONCAT）
FullMsg := CONCAT_3(
    IN1 := 'Error: ',
    IN2 := INT_TO_STRING(#ErrorCode),
    IN3 := ' at line '
);

// 字符串查找
Pos := FIND(IN1 := #Message, IN2 := 'Error');

// 数值转字符串
TextValue := REAL_TO_STRING(#Temperature);
AT 覆盖与间接寻址
// AT 指令：以不同类型覆盖同一内存
// 常用于按字节/位访问 WORD/DWORD
VAR
    ControlWord : WORD;
    ControlBits : ARRAY[0..15] OF BOOL
                        AT #ControlWord;  // 覆盖访问
END_VAR

// 现在可以用 ControlBits[0] 访问 ControlWord 的第 0 位
IF #ControlBits[3] THEN
    "Tags".Alarm := TRUE;
END_IF;

// PEEK/POKE：绝对地址间接读写
// 读 DB1.DBW10 的值
Val := PEEK_WORD(area := 16#84, // DB 区域
                     dbNumber := 1,
                     byteOffset := 10);

// 写 DB1.DBW20
POKE_WORD(area := 16#84,
             dbNumber := 1,
             byteOffset := 20,
             value := 32767);

💡 优化块访问模式下推荐用符号寻址，PEEK/POKE 仅在特殊场景（如跨 DB 动态访问）使用。

类型转换
// SCL 类型转换函数
// 基础转换
RealVal := INT_TO_REAL(#IntVal);
IntVal  := REAL_TO_INT(#RealVal);
DintVal := INT_TO_DINT(#IntVal);

// 带小数位的 REAL 转 INT
Scaled := REAL_TO_INT(#Temperature * 10.0);
// 例：25.6℃ → 256（放大 10 倍存储）

// CONVERT 通用转换
Out := CONVERT(INT, #In);

// ROUND / TRUNC / CEIL / FLOOR

Truncated := TRUNC(#RealVal);   // 截断小数

🔷 FBD 功能块图：信号流编程

FBD（Function Block Diagram）用 信号流 的方式表达数据从左到右的传递过程，特别适合 数学运算、PID 调节、模拟量处理 等需要清晰展示信号流向的场景。

元素图形说明
功能块矩形框 + 输入/输出引脚代表一个运算或功能（ADD, PID, MOVE 等）
信号线箭头连线数据从左流向右
连接点● 小圆点多条线汇合点
跳转→|标记|→跨区域连接
FBD 典型应用：温度 PID
// FBD 信号流示意
// ┌──────────┐   ┌──────┐   ┌──────┐   ┌──────────────┐
// │ Setpoint │──→│ PID  │──→│ LIMIT│──→│ AQW256 (AQ)  │
// │ Actual ──→│      │   │ 0-100│   │ 模拟量输出   │
// └──────────┘   └──┬─┘   └──────┘   └──────────────┘
//                   │
//                   ↓
//              ┌──────────┐
//              │ Alarm FB │──→ Q0.5 (报警)
//              └──────────┘

// FBD 表达式：
PID_Output := PID_Compact(
    Setpoint := #SetTemp,
    Input     := #ActualTemp,
    Output    => RawOutput
);
Limited := LIMIT(MN := 0.0, MX := 100.0, IN := #PID_Output);
FBD vs LAD vs SCL 选择
场景推荐语言原因

📐 ISA-88 批次控制标准

ISA-88 是 国际批次控制标准，为工业自动化提供了 统一的物理层级模型和程序层级模型，让不同厂商的控制系统能在同一架构下协作。

ISA-88 的核心是 Phase 状态机，每个 Operation 都有 6 种标准状态：

6 种状态详解：

状态码状态名进入条件核心行为
0Idle初始化 / Complete 后等待 Start 命令
10RunningCmdStart = TRUE执行工艺子步
20PausedCmdPause = TRUE暂停（保留当前子步）

💻 SCL CASE OF 实现状态机

用 SCL 的 CASE OF 语句 驱动 Phase 状态机，是 ISA-88 的标准 SCL 实现方式：

// FB_BatchPhase.scl — ISA-88 Phase 状态机核心
FUNCTION_BLOCK FB_BatchPhase
VAR_INPUT
    CmdStart  : BOOL;    // 启动命令
    CmdPause  : BOOL;    // 暂停命令
    CmdHold   : BOOL;    // 保持命令
    CmdAbort  : BOOL;    // 终止命令
    SetTemp   : REAL;    // 设定温度
    MaxLevel : REAL;    // 最大液位
END_VAR_INPUT

VAR_OUTPUT
    State       : INT;     // 当前状态码
    SubStep     : INT;     // 工艺子步
    Valve_Feed : BOOL;    // 进料阀
    Heater     : BOOL;    // 加热器
    Valve_Drain: BOOL;    // 出料阀
    PhaseDone  : BOOL;    // Phase 完成标志
END_VAR_OUTPUT

VAR
    Level        : REAL;
    ActualTemp   : REAL;
    HoldTimer   : TONR;
    NextState    : INT;
END_VAR
状态机主逻辑
// Phase 状态机 CASE 驱动
// 读取过程数据
Level      := "PhaseDB".Level;
ActualTemp := "PhaseDB".Temp;

// 定时器（始终调用）
HoldTimer(IN := (State=30), PT := T#30S);

// 默认：下一状态 = 当前状态（自循环）
NextState := State;

CASE State OF
    0:  // Idle
        IF #CmdStart THEN
            SubStep := 10;   // 进入加料子步
            NextState := 10;  // → Running
        END_IF;

    10: // Running — 工艺子步嵌套
        // 1. 先判断命令优先级
        IF #CmdAbort THEN
            NextState := 99;  // → Aborted
        ELSIF #CmdPause THEN
            NextState := 20;  // → Paused
        ELSIF #CmdHold THEN
            NextState := 30;  // → Held
        ELSE
            // 2. 工艺子步嵌套 CASE
            CASE SubStep OF
                10: // 加料
                    Valve_Feed := TRUE;
                    IF #Level >= #MaxLevel THEN
                        Valve_Feed := FALSE;
                        SubStep := 20;  // → 升温
                    END_IF;

                20: // 升温
                    Heater := TRUE;
                    IF #ActualTemp >= #SetTemp THEN
                        Heater := FALSE;
                        SubStep := 30;  // → 保温
                    END_IF;

                30: // 保温（计时 30s）
                    IF #HoldTimer.Q THEN
                        SubStep := 40;  // → 出料
                    END_IF;

                40: // 出料
                    Valve_Drain := TRUE;
                    IF #Level <= 0.0 THEN
                        NextState := 90;  // → Complete
                    END_IF;
            END_CASE;
        END_IF;

    20: // Paused — 暂停时关闭所有输出
        Valve_Feed := FALSE;
        Heater     := FALSE;
        Valve_Drain:= FALSE;
        IF NOT #CmdPause THEN
            NextState := 10;  // → 恢复 Running
        END_IF;

    30: // Held — 保持当前输出不变
        IF NOT #CmdHold THEN
            NextState := 10;
        END_IF;

    90: // Complete — 正常完成
        Valve_Drain := FALSE;
        PhaseDone := TRUE;
        NextState := 0;  // → Idle

    99: // Aborted — 异常终止
        Valve_Feed := FALSE;
        Heater     := FALSE;
        Valve_Drain:= FALSE;
        IF NOT #CmdAbort THEN
            NextState := 0;  // → Idle
        END_IF;
END_CASE;

// 状态转换：一周期延迟避免竞争
State := NextState;
关键设计要点
  • 命令优先级：Abort > Pause > Hold > Start，CASE 中先判断高优先级命令
  • 自循环赋值：`NextState := State` 确保默认保持当前状态
  • 子步嵌套：Running 状态内嵌第二个 CASE 驱动工艺子步（加料→升温→保温→出料）
  • 定时器始终调用：HoldTimer 放在 CASE 外面，每个扫描周期都执行
  • 输出归位：Paused/Aborted 状态必须关闭所有安全相关输出
  • PhaseDone 标志：Complete 时置 TRUE 通知上层 Operation 完成
⏳ 一周期延迟与竞争条件

在状态机中，当前状态决定输出，输出决定下一状态。如果在同一个扫描周期内直接 `State := NextState`，可能导致 竞争条件（当前状态的 CASE 分支还在执行时状态已变）。

❌ 错误：无延迟直接赋值
// ❌ 问题：State 在 CASE 内部改变
CASE State OF
    0: IF #CmdStart THEN
            State := 10;  // 当前周期内 State 变为 10
        END_IF;
    10: // 同一周期内此分支也被执行！
        Valve_Feed := TRUE;  // 不该执行的输出被激活
END_CASE;
✅ 正确：NextState 中间变量
// ✅ 正确：用 NextState 做中间变量
// Step 1: 默认保持
NextState := State;

// Step 2: CASE 根据当前 State 决定 NextState
CASE State OF
    0: IF #CmdStart THEN
            NextState := 10;  // 只改变 NextState
        END_IF;
    10: // 本分支安全执行
        Valve_Feed := TRUE;
        IF #LevelHi THEN
            NextState := 20;
        END_IF;
END_CASE;

// Step 3: 一周期后才赋值
State := NextState;  // 下一周期 State 才更新

💡 这种 读旧值、算新值、末尾赋值 的模式是 PLC 编程的核心范式，与 S7-1200 扫描周期的"输入采样→程序执行→输出刷新"原理一致。

📐 NORM_X / SCALE_X 标度变换

模拟量处理的核心是 从原始数字量（PIW）到工程量（如 ℃、bar、m³/h）的转换。TIA 提供两个标准指令：

NORM_X 归一化
// NORM_X: 将原始值归一化到 0.0 ~ 1.0（REAL）
// 公式：(Value - Min) / (Max - Min)

NormTemp := NORM_X(
    IN    := PIW256,      // 原始 PIW 值（INT）
    MIN   := 0,           // 原始最小值
    MAX   := 27648,       // 原始最大值
    STANDARD := REAL
);

// 例：PIW256 = 13824 → NormTemp = 0.5（50%）
SCALE_X 工程量转换
// SCALE_X: 将归一化值映射到工程量范围
// 公式：Min + Norm * (Max - Min)

ActualTemp := SCALE_X(
    IN    := #NormTemp,    // 归一化值（0.0~1.0）
    MIN   := -50.0,     // 工程量最小值（℃）
    MAX   := 200.0,      // 工程量最大值（℃）
    STANDARD := REAL
);

// 例：NormTemp = 0.5 → ActualTemp = 25.0℃
完整标度变换封装
// FC_ScaleAnalog.scl — 封装完整标度变换
FUNCTION FC_ScaleAnalog : REAL
VAR_INPUT
    RawValue   : INT;      // PIW 原始值
    RawMin    : INT := 0;
    RawMax    : INT := 27648;
    EngMin    : REAL := 0.0;
    EngMax    : REAL := 100.0;
    Filter     : BOOL := TRUE;  // 低通滤波
END_VAR_INPUT

VAR_TEMP
    NormVal  : REAL;
    ScaledVal: REAL;
END_VAR_TEMP

NormVal := NORM_X(IN := #RawValue,
                                 MIN := #RawMin, MAX := #RawMax,
                                 STANDARD := REAL);

ScaledVal := SCALE_X(IN := #NormVal,
                                           MIN := #EngMin, MAX := #EngMax,
                                           STANDARD := REAL);

IF #Filter THEN
    FC_ScaleAnalog := (#LastValue * 0.7) + (#ScaledVal * 0.3);
ELSE
    FC_ScaleAnalog := #ScaledVal;
END_IF;

💡 常用量程速查：0-10V/0-20mA 对应 0~27648（单极性），±10V 对应 -27648~27648（双极性）。

工程快捷公式
// 快速转换公式（不用 NORM_X/SCALE_X）
// 温度：0~100℃ 对应 0~27648
Temp := 100.0 * INT_TO_REAL(#PIW) / 27648.0;

// 压力：0~10 bar 对应 0~27648
Pressure := 10.0 * INT_TO_REAL(#PIW) / 27648.0;

// 电流：4-20mA 对应 5530~27648
Current := 4.0 + 16.0 * (INT_TO_REAL(#PIW) - 5530.0) / 22118.0;

// 电压：0-10V 对应 0~27648
Voltage := 10.0 * INT_TO_REAL(#PIW) / 27648.0;

这些公式等价于 NORM_X + SCALE_X 两步合并，计算更快。

🎛 PID_Compact：工艺对象自整定

PID_Compact 是 TIA Portal 内置的 工艺对象（Technology Object），提供完整的 PID 功能：自整定、抗饱和、输出限幅、跟踪模式。

功能说明使用场景
预调节（Pretuning）阶跃响应识别 PID 参数首次启动时自动整定
精确调节（Fine-tuning）优化动态响应预调节后进一步优化
抗积分饱和输出超限时暂停积分防止积分饱和
跟踪模式手动/自动无扰切换手动操作后平滑切入自动
输出限幅0~100% 或自定义范围保护执行器

✏ SCL 手写 PID 与抗饱和

当 PID_Compact 不满足需求（如自定义算法、多回路耦合）时，可以用 SCL 手写位置式 PID：

// FB_PID_Hand.scl — 手写位置式 PID
FUNCTION_BLOCK FB_PID_Hand
VAR_INPUT
    Setpoint  : REAL;      // 设定值
    Input     : REAL;      // 过程值
    Kp        : REAL := 1.0;  // 比例增益
    Ti        : REAL := 10.0; // 积分时间（秒）
    Td        : REAL := 1.0;  // 微分时间（秒）
    Cycle     : REAL := 0.1; // 采样周期（秒）
    OutputMin : REAL := 0.0;
    OutputMax : REAL := 100.0;
    Manual    : BOOL;
    ManualVal : REAL;
END_VAR_INPUT

VAR_OUTPUT
    Output     : REAL;
    P_Out      : REAL;    // 比例分量（调试用）
    I_Out      : REAL;    // 积分分量
    D_Out      : REAL;    // 微分分量
END_VAR_OUTPUT

VAR
    LastInput  : REAL;    // 上次过程值
    Integral   : REAL;    // 积分累积
END_VAR
位置式 PID 核心算法
// 误差
Error := #Setpoint - #Input;

// 比例分量
P_Out := #Kp * #Error;

// 积分分量（带抗饱和）
IF NOT #Manual THEN
    // 抗饱和：输出在限幅内才积分
    I_Out := #Integral + (#Kp / #Ti) * #Error * #Cycle;

    IF (#P_Out + #I_Out + #D_Out) > #OutputMax THEN
        I_Out := #OutputMax - #P_Out - #D_Out;
    ELSIF (#P_Out + #I_Out + #D_Out) < #OutputMin THEN
        I_Out := #OutputMin - #P_Out - #D_Out;
    END_IF;
END_IF;

// 微分分量
D_Out := #Kp * #Td * (#Error - #LastError) / #Cycle;

// 计算输出
Output := #P_Out + #I_Out + #D_Out;

// 输出限幅
IF #Output > #OutputMax THEN
    Output := #OutputMax;
ELSIF #Output < #OutputMin THEN
    Output := #OutputMin;
END_IF;

// 手动模式
IF #Manual THEN
    Output := #ManualVal;
    I_Out := #ManualVal - #P_Out - #D_Out;  // 跟踪积分
END_IF;

// 保存状态
Integral := #I_Out;
LastError := #Error;
PID 调试口诀
  • 调参顺序：先调 P → 再加 I → 最后加 D
  • 只有 P：增大 Kp → 响应快但稳态误差大
  • 加入 I：减小稳态误差，但太大容易震荡
  • 加入 D：抑制超调，改善动态响应
  • 口诀：P 管现在，I 管过去，D 管将来
  • 响应类型：欠阻尼（有超调）→ 临界阻尼（最佳）→ 过阻尼（慢但稳定）

💡 工业温度控制典型参数：Kp = 2~5, Ti = 30~120s, Td = 5~20s。流量控制：Kp = 0.5~1, Ti = 5~10s。

关键原则 & 避坑

  • 按任务选语言：位逻辑类继续用 LAD（可读性+监控方便）；批量运算/PID/解析用 SCL；顺序工艺用 S7-GRAPH。不要混用。
