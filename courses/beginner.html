PLC 工作原理与数据类型

搞懂 PLC 扫描周期（输入采样→程序执行→输出刷新），理清进制（DEC/HEX/BIN）与基本数据类型（BOOL/INT/DINT/REAL/WORD/DWORD）。
扫描周期 数据类型 存储器区 I / Q / M / DB
🔁 PLC 扫描周期原理

PLC 的工作方式是 循环扫描，而非 PC 的中断响应。每个扫描周期分为 4 个阶段：

1初始化
→
2输入采样
读 I 区 → 写入输入映象区
→
3程序执行
CPU 逐条执行 OB/FB/FC
→
4输出刷新
输出映象区 → 写 Q 区
→
↺ 下一周期

关键概念：

  • 扫描时间 (Scan Cycle Time)：S7-1200 通常 1~10ms，S7-1500 约 0.5~3ms。程序越长扫描越慢。
  • 输入映象区：扫描周期开始时锁存 I 端子状态，周期内即使外部信号变化，映象区不变。
  • 输出映象区：程序执行结果暂存于此，周期末尾统一刷新到 Q 端子。
  • 立即刷新 (Immediate I/O)：用 WIW（立即读）/ WOW（立即写）可跳过映象区，适合高速响应。
  • 保持型扫描：S7-1200 默认启用，扫描周期超时自动触发 OB85 诊断。
📊 基本数据类型

TIA Portal 支持 IEC 61131-3 标准数据类型，编程时必须指定类型。常见类型如下：

类型位长取值范围典型用途
BOOL1 bitTRUE / FALSE开关量（电机启停、气缸到位）
BYTE8 bit0 ~ 255状态码、协议字节
WORD16 bit0 ~ 65535无符号计数器、频率值
DWORD32 bit0 ~ 4294967295脉冲累积、时间戳
INT16 bit-32768 ~ 32767有符号温度、位置
DINT32 bit-2³¹ ~ 2³¹-1大范围计数、流量累积
REAL32 bit±1.18×10⁻³⁸ ~ ±3.4×10³⁸浮点温度 / 压力 / PID 调节
LREAL64 bit双精度浮点高精度算法、复杂运算
TIME32 bitT#0ms ~ T#24d定时器 / 延时
STRING可变最多 254 字符HMI 显示文本、配方名
DATE_AND_TIME64 bitDT#2000-01-01 ~ 2099时间戳、数据记录

进制说明：LAD/SCL 中可用 2#（二进制）、16#（十六进制）、10#（十进制）、8#（八进制）表示字面量。例如 16#FF = 2#11111111 = 255。

💾 PLC 存储器区详解

PLC 内部有多个存储区，每个区用途和访问方式不同。S7-1200/1500 主要存储器区：

区名前缀用途寻址示例备注
输入映象区I外部开关/传感器状态缓存I0.0, IW1, ID2扫描周期开始时锁存，只读
输出映象区Q程序执行结果缓存Q0.1, QW2扫描周期末尾刷新到端子
内部标志区M中间继电器、状态标志M0.0, MW10断电保持型 M 区：MB0~MB31
定时器区TS5/S7 传统定时器T0, T37S7-1200 推荐用 IEC 定时器
计数器区C传统计数器C0, C10同定时器，IEC 计数器更灵活
数据块DB用户定义数据存储DB1.DBD0, "DB".Tag优化块访问推荐符号寻址
局部数据栈LFC/FB 临时变量L0.0, LW1块退出时释放，不持久
外设地址区P直接访问 I/O 硬件PIW256, PQW256立即读写，不经过映象区
🔍 I / Q / M / DB 四大核心区深入
I 区输入映象区 Input

PLC 扫描周期 开始时将外部输入端子（数字量 DI / 模拟量 AI）状态读入 I 区。程序执行过程中读取的 I 值始终是这个快照，不会随外部变化而变化。

// I 区寻址示例
%I0.0  // 位寻址（第 0 字节第 0 位）
%IW0   // 字寻址（AIW0 模拟量输入值）
%ID0   // 双字寻址（32 位数据）

// 推荐：使用符号寻址
"StartButton"  // 对应 I0.0，可读性好

💡 实际应用：急停按钮接 I0.0，传感器接 I0.1~I0.7，模拟量温度传感器接 AIW256。

Q 区输出映象区 Output

程序执行过程中运算的结果暂存于 Q 区，扫描周期 末尾统一写入输出端子（DO / AQ）。因此同一周期内 Q 区可能被多次赋值，但只有最后一次生效。

// Q 区寻址示例
%Q0.1  // 位寻址（电机启动输出）
%QW2   // 字寻址（AQW2 模拟量输出，如 PID 调节输出）

// 自锁电路：Q0.1 同时作为条件和输出
// 扫描周期内读到的 Q0.1 是上一周期的值

💡 实际应用：电机接触器接 Q0.1，气缸电磁阀接 Q0.2，模拟量 PID 输出接 AQW256。

M 区内部标志区 Merker

M 区是 PLC 的 内部存储区，用于存储中间运算结果、状态标志、计数器/定时器当前值。M 区不直接对应外部端子，仅在 CPU 内部运算时使用。

// M 区典型用途
M0.0  // 中间继电器（启保停逻辑中的自锁触点）
M10.0 // 故障标志（电机过载）
MW20  // 运算中间值（计数累积）
MD30  // 32 位运算结果

// M 区保持型：MB0~MB31 断电保持
// S7-1200 M 区总容量：4096 字节

💡 实际应用：自锁逻辑用 M0.0 替代 Q0.1 避免竞争；故障标志用 M10.0~M10.7 做报警汇总。

DB 区数据块 Data Block

DB 区是 用户可定义的存储区，用于存储大量参数、配方、运行数据。S7-1200/1500 推荐使用 优化块访问（默认开启），通过符号名访问，不再使用绝对地址。

// DB 区访问方式
// 传统绝对寻址（非优化块）
%DB1.DBD0   // 数据块 1 的双字偏移 0

// 推荐符号寻址（优化块）
"MotorDB".CurrentSpeed   // 读电机当前转速
"RecipeDB".Tank1.Volume  // 读配方罐 1 容量

// DB 类型
// ① 实例 DB（背景 DB）：绑定 FB/FC 接口
// ② 全局 DB：通用数据存储
// ③ UDT 类型 DB：用户自定义数据结构

💡 最佳实践：每个设备配一个独立 DB（如 Motor_DB、Conveyor_DB），用 UDT 定义结构，多实例 FB 共享。

学习建议

  • TIA Portal 安装路径千万不要有中文（C:\TIA\Pro\ 这种），否则编译/下载莫名其妙报错。
  • 先用 PLCSIM 无硬件练习，每个指令要看到效果，不要只看书。
  • 符号表 Tag 必须命名（Motor_Start、Conveyor_Speed 这种），不要写 I0.0、M0.0，用 M 区是坏习惯。
  • 快捷键尽早用起来，Ctrl+K 搜索、Ctrl+L 在线、F11 编译是三大件。
  • 入门完成后务必接 进阶篇 · 结构化编程，否则 OB1 会越来越乱。
